狐狸为什么变成华夫饼

鉴定对象：Codex 拍的 11 部小萌物短片 ｜ 鉴定屏幕：宝的手机（375 宽、3 倍屏）

1同一部片、同一秒、两块屏幕

《神秘来客》第 79 秒。左边是你的手机，右边是宽一点的 iPhone（414 宽）。片子一个字没改，换的只是屏幕。

都是屏幕真像素截下来再放大的。手机原尺寸下，这只猫大概只有一个指甲盖大。

2自己烤一块

下面三格画的是同一只小萌物、同一个放大倍数，只是画法不一样（甲、丁的叫法和第 3 节普查表对得上）。拖一下滑条，看看抽到哪张签。

《神秘来客》在这些屏幕上的放大倍数：
放大倍数2.75
甲 · 逐格画，先取整再放大
Codex《神秘来客》这种（打开「歪 7°」就是乙）
cc 款 · 先放大，再取整
cc、build、Argon 的正片都是这种
丁 · 先画成 20×13 小图，再整张放大
Codex《银幕外的珠子》这种
缝是怎么漏出来的：手机屏幕是一格一格的发光小方块（真像素）。一格猫的边如果正好落在某个真像素的正中间，浏览器只能把那个真像素涂一半——这叫「抗锯齿」，本意是让斜线不毛糙。隔壁那格再来补另一半，可它补的是「剩下部分的一半」：50% + 50% × 50% = 75%。
两个半块拼不回一整块，剩下 25% 是背景色。每条格子边都漏一点，连起来就是华夫饼。

3普查：Codex 的 11 部，在你手机上

每 0.5 秒停一帧，数狐狸和猫的格子之间有多少条边落在半格上。「帧」只算狐狸或猫在画面里的那些。

进仓库片子画法你手机上
  • 甲逐格画：在 360 宽的稿纸上取整，再整张乘上放大倍数
  • 乙逐格画：画布不变，角色自己缩放、歪头，或者镜头推近
  • 丙同色的格子合成一笔画（代码里自带一句防缝注释）
  • 丁先画成 20×13 的小图，再整张放大
  • 戊和甲一样逐格画，但在你手机上画布刚好 1:1

终端推进仓库的 6 部里，只有出道作《神秘来客》是华夫饼（它进仓库 34 分钟后就被挪进了博物馆）；你自己上传的 5 部里，有 3 部。

另外三家，同一台手机

grok 小卡里剩下那 1 部是《取景》，有 8 帧冒出过一两条，看不见。
真正漏的是 grok 博物馆里的《少一圈》《找零不必了》《也行这单》，每一帧都有缝。这三部都没用 cc 的骨架，是 build 自己从零写的。

4差的就是一个顺序

// cc / build / Argon：
// 先乘放大倍数，再取整到真像素
function px(v){ return Math.round(v*S); }
ctx.fillRect(px(x), px(y),
  px(x+w) - px(x), px(y+h) - px(y));

// Codex《神秘来客》：
// 先在 360 宽的稿纸上取整，再整张乘 S
x = Math.round(x);
g.setTransform(S,0,0,S,0,0);
g.fillRect(x+i*n, y+j*n, n, n);
// 你手机上 S = 2.75，
// 每格的边落在 .25 / .50 / .75

Codex 这部片的开头注释写着「借鉴 CC《凑近一点》《接住秋天》」。骨架确实是照着抄的：同样的 360×640 稿纸、同样的 setup(pxW)、同样用屏幕宽度乘倍数——唯独没抄 px() 那一行。它还特意写了一句 imageSmoothingEnabled=false（关掉平滑）：咒语没念错，念错了对象，这个开关只管贴图，管不着画方块的边。

歪头的时候

你上传的那三部华夫饼（乙）是另一种漏法：画布没被放大，是角色自己缩放成 0.9 倍、1.05 倍，歪上几度，或者镜头推近，格子边一样落到半格上。这种跟屏幕无关，哪块屏都漏。取整救不了斜线，只有丁扛得住：先把 20×13 的格子画成一张小图，再整张转、整张放大。这一招 Codex 自己在三部片里用过。

怎么量的：在 Chromium 里按你的手机打开每部片（375×812、3 倍屏，是从你之前诊断页量到的 812 高推出来的），借每部片自带的 FILM.render(t) 每 0.5 秒停一帧，记下狐狸和猫的每一格落到画布真像素上的位置，数相邻两格之间、由不同两笔画出来、又落在半格上的边。不是真 iPhone：Safari 的抗锯齿细节可能和 Chromium 有出入，但「半格必漏底」两边一样。
