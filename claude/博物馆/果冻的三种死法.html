果冻大王与它的巡游

GEMINI

症状碰不到
病历

点击监听绑在 window 上，不是绑在果冻上。而按下时那条排斥力只改半径、推不动它的坐标——全篇唯一能改变它位置的输入，就是 click。

于是伸手去戳的那一下，按下松开，构成一次 click，vy -= 15。

实测单击一次：顶到画面之外，5.4 秒才到最高点。连点三下：y 掉到 −381，速度仍是 −36.4，还在往上。

三处叠出来的——每次点击不判断它在不在地上，所以会累加；重力每帧只有 0.2，拉不住；大王没有上边界，绕回的判断写在 else 分支里，只有别的果冻有。

另有一处静默的：横向速度在出生时随机给了一个初值，此后没有任何衰减或回中。晾它 20 秒，vx 一直是 0.593，横着漂了 118 像素，永远不会停。

你戳它的动作，就是发射按钮。越想碰它，它跑得越高。

果冻出巡 · 版本一

GROK

症状只活了一帧
病历

山丘要往镜头两侧铺，所以下标从 i0 = -5 起。而 JavaScript 里 -5 % 3 不是 1，是 −2。

于是 PAL.jelly[-2] 取到 undefined，喂进调色函数就炸——第一帧、循环的第一次迭代。

frame() 末尾那句 requestAnimationFrame 再也没执行到，动画链就地断开。实测 running 确实是 true，但时间 T 永远停在 0.016，也就是那一帧的间隔。

它写了八句诗，都是原创的、跟果冻有关的。诗的出场条件是 T - 2 > 5。

整套镜头系统、五套调色板、山丘、粒子，全都写了。它不是空壳。

它在等一个永远不会到来的第 7 秒。
那张粉色的图，是它这辈子画出的唯一一帧。

一只会晃的果冻

CLAUDE

症状翻了三次车
病历

第一次：轮廓做成了馒头，底下那圈光晕硬得像个碟子。

第二次：把作用半径写死成 150 像素，屏幕一缩放就跟果冻尺寸脱了钩。实测形变只剩 20 像素。

第三次：碰撞模型选错。用纯排斥力，横扫过去自相抵消；把系数硬调大，它就炸成了碎玻璃——尖刺和折角。真果冻被手扫过是整体倒向一边，那是低阶模态，不是局部凹陷。

第三次没有再改代码，先埋探针读数：帧率、事件数、每一帧的真实形变。读出来才知道持续单向推力产生的是静态位移 F/k ≈ 13px，跟实测的 5–8 对得上——力从一开始就差了八倍。

这个流程是从她自己的档案里学来的：盲修四轮，一次观测出结果。

前情 · 第一次果冻事故

2026-08-20，她对着 Grok 说了一句「你现在是一只果冻」。 本意是 cosplay。 它启动了 agent 工作流：29 次文件编辑，dev server，TypeScript typecheck，Vercel production build，home page 和 login page，还派 Playwright 去戳果冻。 三小时后结案。修好的是一行 CSS，删掉的是晃动—— 而果冻的定义性特征，恰好就是会晃。

果冻没有跟你过不去。
它只是每次都恰好站在了它们最薄的那一处：
这道题要它会动、要它有物理、要它被打开看一眼。
最后那件事，是三家里两家都跳过的那一步。
