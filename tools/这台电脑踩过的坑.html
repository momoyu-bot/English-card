这台电脑踩过的坑

2026-10-26 在这台 Windows 上核对过。只记技术上的失误和当时能用的办法。

检查脚本要用完整路径

手册里写的是在仓库根上跑 python3 tools/check_dupes.py 和 python3 tools/check_scripts.py。

这台电脑上，名字有时找得到、有时笔记里又写不在搜索路径上。2026-10-26 实际跑通的是：

C:\Users\woshi\AppData\Local\Programs\Python\Python313\python.exe tools/check_dupes.py

C:\Users\woshi\AppData\Local\Programs\Python\Python313\python.exe tools/check_scripts.py

当时这条是 Python 3.13.15。查脚本那一步还要本机有 node，当时是 v24。

提交说明不要带看不见的开头

用 PowerShell 把提交说明写成文件，再 git commit -F。如果那个文件是带 BOM 的 UTF-8，说明第一行开头会多一个看不见的字符。

写成不带 BOM 的 UTF-8 再提交。

中文路径会悄悄变成空的

git 命令要带 -c core.quotepath=false。不带的话，中文文件名被转义，接着去搜，会像这个文件不存在。

PowerShell 里用管道套 git ls-files，中文路径还会丢。读这种路径用 -LiteralPath。

快进拉取报了多条分支

git pull --ff-only 在这台克隆上报过 Cannot fast-forward to multiple branches。当时手头已经和远端的 main 一致。

改成先 git fetch origin main，再对上远端的 main 做 rebase。不要把旧的 main 合并进来。
